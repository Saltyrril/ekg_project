## О проекте

**ЭКГ** записывает электрическую активность сердца. Стандартная ЭКГ состоит из **12 отведений** (12 «ракурсов» на сердце), и врач ищет в ней признаки инфаркта, нарушений проводимости, утолщения сердечной мышцы и другого.

Проект обучает модель на **PTB-XL**, большом открытом датасете ЭКГ: она читает 10-секундную запись из 12 отведений и выдаёт вероятность для каждого из **пяти диагностических суперклассов**:

| Класс | Смысл |
|---|---|
| NORM | норма |
| MI | инфаркт миокарда |
| STTC | изменения ST–T |
| CD | нарушения проводимости |
| HYP | гипертрофия |

Задача **multi-label**: одна запись может относиться сразу к нескольким классам, поэтому пять вероятностей не обязаны давать в сумме 1.

Цель не в продукте, а в **честном исследовательском конвейере** для портфолио:

- **Строгий протокол данных.** Обучение на фолдах 1–8, всё подбирается на фолде 9, тестовый фолд 10 используется **ровно один раз** в самом конце. Статистики нормализации считаются только по train.
- **Два вида моделей.** Бейзлайн LightGBM на ручных признаках против 1D-свёрточных сетей на сыром сигнале.
- **Неопределённость, а не только точечные значения.** 95% доверительные интервалы на test (bootstrap по пациентам), парное сравнение моделей.
- **Калибровка.** Можно ли доверять предсказанным вероятностям? Температура, подобранная на val, ECE и Brier.
- **Взгляд внутрь модели.** Карты Integrated Gradients с контролями, которые показывают, что они доказывают, а что нет.
- **Локальное приложение:** загружаете свой файл ЭКГ и получаете проверку качества сигнала, вероятности, карты значимости и PDF-отчёт.

### Главный результат (test, фолд 10, оценён один раз)

| | 1D-CNN + аугментации | LightGBM по признакам |
|---|---|---|
| macro AUROC | **0.922** [0.914, 0.929] | 0.880 [0.871, 0.889] |
| macro PR-AUC | **0.811** [0.794, 0.827] | 0.739 [0.719, 0.757] |
| macro F1 (пороги с val) | **0.743** [0.727, 0.757] | 0.666 [0.649, 0.681] |

## Данные и разбиение

- **PTB-XL**, версия 100 Гц, 12 отведений.
- Метки: коды `scp_codes` из `ptbxl_database.csv`, суперкласс по `diagnostic_class` из `scp_statements.csv`. Учитываются все коды независимо от likelihood (`min_likelihood: 0`, как в бенчмарке PTB-XL).
- Записи без суперкласса исключаются, их число логируется: **train 334, val 37, test 40**.
- Разбиение по готовому `strat_fold`. Любое другое разбиение вызывает `ValueError` в `src/data.py`.

| Выборка | Фолды | Для чего | Записей |
|---|---|---|---|
| train | 1–8 | обучение, статистики нормализации | TODO (в `results/experiments.csv`, `summary.md` и `final/metrics.json` не указано) |
| val | 9 | выбор модели, early stopping, температура T, пороги | TODO (то же) |
| test | 10 | только финальная оценка, один раз | 2158 (1877 пациентов) |

- Нормализация: z-score по каждому отведению, mean/std только по train.
- Доли классов на test: NORM 0.446, MI 0.255, STTC 0.241, CD 0.230, HYP 0.121.
- Кэш данных сверен с CSV PTB-XL (`scripts/verify_cache.py`, отчёт `results/final/cache_check.json`) после финального прогона, проверка пройдена: фолды, набор записей, метки, `patient_id` и статистики нормализации совпали, общих пациентов между выборками нет.

## Методы

**Бейзлайн: LightGBM** (`src/features.py`, `src/baseline.py`, `configs/baseline.yaml`). 12 статистик по каждому из 12 отведений + ритм и интервалы (ЧСС, RR, PR, QRS, QT, QTc) через neurokit2; итого 156 признаков (вариант `stats_plus_neurokit`). Один бинарный LightGBM на класс (one-vs-rest), ранняя остановка по AUROC на val. Интервалы при 100 Гц грубые и смещённые, их стоит читать как относительные признаки, а не клинические значения.

**Нейросети** (`src/models.py`, `src/train.py`, `configs/*.yaml`); модели отдают логиты, sigmoid применяется снаружи.
- `cnn1d`: 5 блоков Conv1d–BatchNorm–ReLU–MaxPool (каналы 32/64/128/256/256, ядро 7), голова: среднее и максимум по времени, Dropout 0.3, Linear. 766 533 параметров.
- `resnet1d`: ResNet-18 для 1D (stem с ядром 15 и stride 2, 4 ступени по 2 блока), та же голова. 2 192 197 параметров.
- Обучение: BCEWithLogitsLoss, AdamW, разогрев 1 эпоха и косинусный спад lr, mixed precision (float16), batch 128, early stopping по val macro AUROC, seed 42. `pos_weight` выключен: он завышает вероятности и портит калибровку. Выходной bias инициализирован как logit доли класса в train.
- Аугментации (`src/augment.py`, только train): сдвиг по времени ±0.5 с, масштаб амплитуды ×U(0.8, 1.2), дрейф изолинии, гауссов шум; каждая с p = 0.5. Варианты `*_aug` отличаются от базовых только ими.

**Постобработка и оценка** (`src/evaluate.py`): одна общая температура T для всех классов (по NLL на val), затем пороги по максимуму F1 на откалиброванных вероятностях val. Для `cnn1d_aug`: T = 1.473. Доверительные интервалы на test: перцентильный парный bootstrap по `patient_id`, 2000 реплик.

Все параметры лежат в YAML-конфигах, каждый запуск пишет конфиг, метрики и время в `results/`.

## Эксперимент с отведениями
Вопрос: сколько отведений нужно модели? Одна и та же `cnn1d_aug` (конфиги `configs/cnn1d_aug_leads_*.yaml` отличаются только набором отведений, остальное идентично `cnn1d_aug`) обучена на подмножествах отведений. Источник: `results/experiments.csv`, `results/summary.md`. **Только val (фолд 9), один seed**, test не использовался.

| Отведения | Число | macro AUROC | NORM | MI | STTC | CD | HYP |
|---|---|---|---|---|---|---|---|
| I | 1 | 0.8442 | 0.8882 | 0.8005 | 0.8842 | 0.8357 | 0.8123 |
| I, II | 2 | 0.8992 | 0.9310 | 0.8979 | 0.9116 | 0.9106 | 0.8449 |
| I, II, III, AVR, AVL, AVF | 6 | 0.9014 | 0.9318 | 0.9016 | 0.9124 | 0.9156 | 0.8454 |
| все 12 | 12 | **0.9277** | 0.9405 | 0.9272 | 0.9316 | 0.9351 | 0.9041 |

- Контрольный запуск `leads_all12` воспроизвёл `cnn1d_aug` по AUROC и PR-AUC (0.9277 и 0.813).
- Переход с одного отведения на два даёт +0.055 macro AUROC, с шести на двенадцать — +0.026; шесть отведений от конечностей практически не лучше пары I, II (+0.002, это в пределах шума одного seed).
- Сильнее всего от нехватки отведений страдает HYP: 0.9041 при 12 отведениях против 0.8454 при 6. Объяснение (грудные отведения несут информацию о гипертрофии) — гипотеза, она этим экспериментом не проверялась.
- Модель на одном отведении I (0.8442) уже ниже LightGBM на 12 отведениях (0.8939, val), то есть для этого набора признаков и архитектуры одно отведение заметно хуже. Вывод о пригодности носимых устройств отсюда не следует.

## Калибровка
Источник: `results/final/metrics.json` (test). Калибровка — одна общая температура T, подобранная на val: у CNN T = 1.473, у LightGBM T = 1.068. ECE — 10 равноширинных бинов (`configs/evaluate.yaml`); меньше — лучше.

| Метрика (test) | CNN, без T | CNN, после T | LightGBM, без T | LightGBM, после T |
|---|---|---|---|---|
| macro ECE | 0.051 [0.047, 0.059] | 0.038 [0.036, 0.046] | 0.028 [0.027, 0.039] | 0.026 [0.025, 0.036] |
| macro Brier | — | 0.087 [0.083, 0.092] | — | 0.107 [0.103, 0.112] |
| macro NLL | — | 0.286 [0.273, 0.300] | — | 0.343 [0.329, 0.357] |

ECE по классам после T (test): CNN — NORM 0.018, MI 0.052, STTC 0.058, CD 0.020, HYP 0.044; LightGBM — NORM 0.040, MI 0.025, STTC 0.024, CD 0.021, HYP 0.018.

- Температура уменьшает macro ECE у CNN (0.051 → 0.038); на val то же направление (0.048 → 0.038, cross-fit).
- По Brier и NLL CNN лучше LightGBM (разница Brier −0.020 [−0.023, −0.017]).
- По бинированному ECE точечное значение у LightGBM ниже (0.026 против 0.038), но надёжного вывода сделать нельзя: bootstrap-ДИ бинированного ECE смещены вверх (шум выборки добавляется к ошибке калибровки), интервалы могут не накрывать точечное значение. Для сравнения калибровки Brier надёжнее.
- Калибровка по классам (`temperature: per_class`): TODO, не проводилась.

## Локальное приложение

`python app/app.py`, затем http://127.0.0.1:7860 (нужен собранный `app/model`, см. [Как запустить](#как-запустить)). Работает целиком на вашем компьютере и ничего никуда не отправляет. Принимает:

| Формат | Что загрузить | Примечания |
|---|---|---|
| WFDB | `<имя>.hea` + `<имя>.dat` | единицы и частота берутся из заголовка |
| EDF / EDF+C | один `.edf` | каналы по именам (`ECG I`, `aVR`, `V1` …), единицы по заголовку; EDF+D не поддерживается |
| CSV / TXT | один файл: столбцы I, II, III, aVR, aVL, aVF, V1–V6, строка = отсчёт | заголовок желателен; без него ровно 12 столбцов в этом порядке; частота из столбца времени либо вводится вручную; единицы (мВ/мкВ/В) выбираются в интерфейсе; допустимы `;`, табуляция, десятичная запятая |

Запись должна быть не короче 10 с (берутся первые 10 с) и от 100 Гц; частоты выше пересчитываются в 100 Гц (250, 256, 360, 500, 1000 и др.). Нужны все 12 отведений; PDF, фото и бумажные ЭКГ не поддерживаются.

**Проверка качества** (`app/quality.py`, эвристики на scipy, без обучения) ставит статус «хорошее / есть замечания / низкое» и перечисляет замечания: плоские отведения и обрывы, ВЧ-шум, дрейф изолинии, нет комплексов QRS (шум вместо ЭКГ), нереальные амплитуда и пульс (признак неверных единиц), несогласованность отведений по Эйнтховену (перепутанные электроды или порядок), дубликаты отведений. При статусе «низкое» ответ модели помечается «ненадёжно». Пороги проверены на val (фолд 9, test не читался): `python scripts/check_quality.py` → `results/2026-11-06_quality_check/`. Из этого прогона:
- чистые val-записи получают «хорошее» в 88.9% (замечания у 11.0%, «низкое» примерно у 0%);
- плоское отведение, обрыв сигнала, неверные единицы (×1000, ×0.001) и шум вместо ЭКГ ловятся в 100% искусственных случаев, перестановки отведений — как замечание в 100%;
- ограничения: сильный шум или дрейф получает «низкое» только при поражении ≥6 отведений (при шуме 0.2 размаха, который роняет macro AUROC модели на 0.11, это лишь 13% записей, остальные — «есть замечания»);
- пометка шума `static_noise` из PTB-XL не воспроизводится (4% против 12% у остальных), дрейф `baseline_drift` — частично (34% против 8%);
- пороги подобраны на PTB-XL и для других приборов могут давать лишние замечания.

**PDF-отчёт** (кнопка в приложении, `app/report.py`, только matplotlib): сводка (запись, качество сигнала, вероятности и пороги классов), 12 отведений, карты значимости для классов выше порога (или для самого вероятного), версия модели (запуск, коммит, sha256 весов, T, пороги), методика и ограничения. Дисклеймер «не медицинский документ» — на каждой странице.

Тесты чтения и проверки качества: `python -m unittest discover -s tests`.

## Ограничения
- Исследовательский прототип, не медицинское изделие: не предназначен для диагностики и клинических решений.
- Val-метрики (фолд 9) оптимистичны: по ним выбирались модель, эпоха, T и пороги. Несмещённая оценка — только test.
- Один seed (42) на модель, разброс между запусками не оценён; разницы ≤0.005 AUROC между вариантами на val — в пределах шума. Сравнение по отведениям тоже на одном seed и только на val.
- ECE не оценён надёжно (смещённые bootstrap-ДИ), вывода о преимуществе в калибровке нет.
- По HYP преимущества CNN над LightGBM нет.
- Бейзлайн на test получен переобучением (веса не сохранялись); его T и пороги подобраны на val той же процедурой, что у CNN. Это решение принято при реализации, после согласования плана, и описано в `docs/decisions.md`.
- Финальный прогон выполнен на «грязном» дереве git (`05a36b3` + незакоммиченные файлы). Версия `src/final_eval.py` этого прогона в git не сохранена (sha1 `a4c0d22f2b33`), поэтому точное воспроизведение из git не гарантировано; цифры в `results/final/metrics.json` — результат того единственного прогона. Повторный запуск запрещён в коде.
- `git_dirty = True` в `results/experiments.csv`: код нейросетей на момент val-запусков не был закоммичен.
- В сводке val есть повторы: `2026-11-05_resnet1d_234721` дублирует `2026-11-05_resnet1d`, `leads_all12` — `cnn1d_aug` (это проверки воспроизводимости, не отдельные эксперименты).
- Частота 100 Гц: детекция интервалов (PR, QRS, QT) грубая; версия 500 Гц не пробовалась.
- Метки PTB-XL — результат автоматической и ручной разметки с разной уверенностью (likelihood); здесь используются все коды без порога. Внешняя валидация на других датасетах: TODO, не проводилась.
- Сравнение с результатами авторов бенчмарка по числам: TODO (в разрешённых источниках чисел бенчмарка нет). Различаются протоколы, поэтому прямое сравнение корректно только при тех же фолдах и метрике.

## Как запустить

Установка (Windows, PowerShell):
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
pip install -r requirements.txt
python scripts/check_env.py   # интерпретатор в .venv, версии из requirements.txt, torch + CUDA
python scripts/check_cuda.py  # подробная проверка GPU
```
Данные: распакованный архив PTB-XL (`ptbxl_database.csv`, `scp_statements.csv`, `records100/`) положите в `data/ptb-xl` (путь задаётся в `configs/data.yaml`). Данные в git не хранятся.

Конвейер:
```powershell
python -m src.data --config configs/data.yaml                    # кэш сигналов, статистики нормализации (только train), лог исключённых
python -m src.baseline --config configs/baseline.yaml            # LightGBM
python -m src.train --config configs/cnn1d_aug.yaml              # нейросеть (также cnn1d, resnet1d, resnet1d_aug, cnn1d_aug_leads_*)
python -m src.evaluate --run results/2026-11-06_cnn1d_aug        # T, пороги, F1, калибровка и графики на val
python -m src.explain --config configs/explain.yaml              # карты значимости на val
python scripts/summarize_results.py                              # results/experiments.csv и results/summary.md
```
Финальная оценка на test выполнена один раз (`results/final/`). Запуск `python -m src.final_eval` остановится, если `results/final/metrics.json` уже существует; режим `--dry-run` проверяет конвейер на val, test не читает. Подбирать гиперпараметры, T, пороги или модель по тестовым цифрам нельзя.

Локальному приложению и статической демо-странице нужен локальный `app/model` (в git его нет):
```powershell
pip install gradio==6.31.0                                     # скрипт импортирует app/app.py
python scripts/export_app_bundle.py --config configs/app.yaml  # app/model; проверяет совпадение с val_probs.npy, test не читает
python app/app.py                                              # приложение на http://127.0.0.1:7860
python scripts/export_static_demo.py --config configs/static_demo.yaml   # пересборка docs/demo
```
Всё обучалось на RTX 3050 Laptop (4 ГБ): mixed precision, batch 128.
