# Журнал решений
- Разбиение: train strat_fold 1-8, val 9, test 10.
- Версия данных: 100 Гц.
- Метки: учитываются все диагностические коды из scp_codes независимо от likelihood
  (min_likelihood: 0), как в бенчмарке PTB-XL. Записи без суперкласса исключаются.
- Нормализация: z-score по каждому из 12 отведений, mean/std только по train.
  В кэше лежат сырые сигналы, нормализация применяется при загрузке (src/data.py:load_splits).
- Test (фолд 10) не загружается по умолчанию: load_splits(splits=("train", "val")).
- Бейзлайн (src/features.py, src/baseline.py, configs/baseline.yaml): 12 статистик × 12 отведений
  по сырому сигналу (мВ) + ЧСС/RR/PR/QRS/QT/QTc через neurokit2 по отведению II; LightGBM
  one-vs-rest на CPU, ранняя остановка по AUROC на val (фолд 9). NaN не заполняются
  (LightGBM их понимает). Интервалы при 100 Гц грубые и смещены (медиана QRS ~160 мс) —
  использовать как относительные признаки, не как клинические значения.
- Результат бейзлайна на val: macro AUROC 0.894 (только статистики: 0.884). Метрика слегка
  оптимистична из-за early stopping по val; test не использовался.
- Нейросети (src/models.py, src/train.py, configs/{cnn1d,resnet1d}.yaml): модели отдают логиты,
  sigmoid снаружи; лосс BCEWithLogitsLoss, AdamW (без decay для bias/BN), разогрев 1 эпоха +
  косинусный спад lr, AMP float16 + GradScaler, early stopping по val macro AUROC (фолд 9).
  Выходной bias инициализируется logit(доли класса в train).
- pos_weight по умолчанию выключен (pos_weight: false): дисбаланс умеренный (HYP ~12% — самый редкий),
  а веса положительных завышают вероятности и портят калибровку, которая есть в списке метрик.
  Это отход от идеи в handoff — включается одной строкой в конфиге.
- Батч 128: замер памяти (--probe-batch) показал пик 0.26 ГБ (ResNet1d) из 4 ГБ, память не ограничивает;
  gradient accumulation поддерживается (grad_accum_steps), но не нужен.
- Аугментации (src/augment.py, секция `augment` в конфиге): сдвиг по времени ±0.5 с, масштаб амплитуды
  ×U(0.8, 1.2), дрейф изолинии (синус 0.05–0.5 Гц, до 0.3 std), гауссов шум (0.05 std), каждая с p=0.5.
  Только train, после z-нормализации (единицы — std отведения), на GPU, свой генератор случайных чисел:
  при `enabled: false` обучение бит-в-бит такое же, как без модуля. Сравнение «с/без» — configs/*_aug.yaml
  против configs/*.yaml; различаются только `experiment_name` и `augment.enabled`.
- Карты значимости (src/explain.py, configs/explain.yaml; результаты — results/figures/<run>/explain/): Integrated Gradients
  по логиту класса, baseline = 0 в z-пространстве (среднее train по отведению), 64 шага, fp32 (не autocast: исключение из
  правила про mixed precision — при fp16 мелкие градиенты обнуляются, записей мало). IG написан вручную, без captum:
  captum не установлен, зависимость не оправдана ~20 строками кода; ошибка полноты проверяется (медиана 0.3%).
  Grad-CAM не взят: у cnn1d последняя карта признаков — 31 шаг (~0.32 с на ячейку), QRS от ST–T на ней не различить.
  Анализ только на val. К самим картинкам приложены контроли: IG случайной модели и тривиальная карта |x|, потому что
  доля QRS в attribution в основном объясняется амплитудой. Окна QRS/ST–T/P заданы от R-зубца (делинеация на 100 Гц
  ненадёжна), R-зубцы ищутся по отведению II — у записей с отрицательным QRS в II (напр. нижний ИМ) окна могут смещаться.
- Окружение: один проектный `.venv`, всё из requirements.txt, torch — по README (cu126; в .venv стоит 2.14.1+cu126, как и
  в системном Python, где ранее обучались модели). Раньше torch был только в системном Python, а neurokit2 и др. — только
  в .venv; на время работы над explain я ставил neurokit2/PyWavelets/setuptools в системный Python — это откатено
  (удалены только они, остальное в системном Python не трогали). Прогон explain из .venv даёт те же числа (макс. расхождение
  7e-7 по 1345 полям explain_val.json). В requirements.txt добавлены scipy (импортируется напрямую; был только транзитивным)
  и packaging (для check_env.py). Проверка окружения: `python scripts/check_env.py` (интерпретатор в .venv, версии из
  requirements.txt, torch с CUDA); глубокая проверка GPU — scripts/check_cuda.py.
- Этап 9 (карты значимости, IG на val, cnn1d_aug) закрыт. Итог: модель чувствительна к QRS (38–48% |IG| при ~16% времени),
  но этот эффект частично объясняется амплитудой (контроль |x| даёт 32–39%, IG случайной модели — 40–48%); вывод про ST–T
  не подтверждён (доля |IG| в ST–T 28–36% при 38–42% времени, не выше доли времени). Стирание топ-участков по IG роняет
  логит сильнее, чем случайных и чем топ по |x|, то есть IG находит влияющие участки, но не доказывает клинически осмысленный
  фокус. Отведения: CD — V1, HYP — V5/V1 (согласуется с известными признаками, но не доказательство). Один seed, одна модель.
  Не сделано и отложено как отдельный этап: разрез MI по IMI/AMI и STTC по подтипам, окна по делинеации на 500 Гц (нужна
  версия данных 500 Гц и пересборка кэша).
- Этап 11, финальная оценка на test (src/final_eval.py, configs/final_eval.yaml, итог — results/final/): выполнена ОДИН раз
  (2026-11-06). Модель cnn1d_aug с T и порогами из её postprocess.json (val). Бейзлайн LightGBM не сохранялся, поэтому
  переобучен тем же кодом и seed (train, ES по val); воспроизведение проверено до чтения test (val macro AUROC и
  best_iteration совпали точно), его T и пороги подобраны на val той же процедурой. Все проверки — до test; конвейер
  сначала прогнан в режиме --dry-run на val. Повторный запуск запрещён в коде (если results/final/metrics.json есть — стоп).
  Прогон шёл на 05a36b3 с незакоммиченными файлами (metrics.json: env.git.dirty = true), они закоммичены в 382a781:
  src/baseline.py, src/evaluate.py, configs/final_eval.yaml там совпадают с env.sha1 прогона (проверено), src/final_eval.py
  после прогона менялся только в части отчёта (текст table.md, флаг --table-only).
  ДИ — перцентильный парный bootstrap по patient_id, 2000 реплик. ДИ для ECE ориентировочный (bootstrap-смещение вверх).
  Test: 2158 записей, 1877 пациентов, исключено без суперкласса 40. cnn1d_aug: macro AUROC 0.922 [0.914, 0.929],
  macro F1 0.743 [0.727, 0.757]; LightGBM: 0.880 [0.871, 0.889] и 0.666 [0.649, 0.681]; разница AUROC +0.042 [0.035, 0.049].
  HYP: разница AUROC +0.013 [−0.001, 0.028] — значимого преимущества нет. Решение по test больше не принимается.
- Решение, принятое ПОСЛЕ согласования плана финальной оценки и заранее НЕ обсуждавшееся с автором проекта
  (принято мной, Claude, при реализации src/final_eval.py, до чтения test). Задача требовала «использовать пороги и
  температуру, подобранные на val», но у бейзлайна их не было: LightGBM не сохранялся, val-вероятности тоже.
  Процедура для бейзлайна: (1) переобучить LightGBM тем же кодом (src/baseline.py: fit_ovr, select_variants), тем же
  конфигом и seed — train для обучения, val (фолд 9) для ранней остановки; (2) до чтения test проверить воспроизведение:
  val macro AUROC и best_iteration по каждому классу должны совпасть с results/2026-11-05_baseline_lightgbm/metrics.json
  (совпали точно, ΔAUROC = 0); (3) подобрать на val ту же постобработку, что у CNN (src/evaluate.py: fit_postprocess —
  одна общая T по NLL, затем пороги по max F1 на откалиброванных вероятностях): T = 1.068, пороги NORM 0.538, MI 0.255,
  STTC 0.324, CD 0.341, HYP 0.202 (results/final/baseline_postprocess.json); (4) применить их к test без пересчёта.
  Альтернативы, которые не обсуждались: сравнивать бейзлайн только по AUROC/PR-AUC (без порогов) или по порогу 0.5.
  Влияние: AUROC/PR-AUC от этого решения не зависят (T монотонна); F1 и ECE бейзлайна зависят.
